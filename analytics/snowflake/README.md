# Snowflake SQL

Every script here was run against the project's Snowflake account. For the design behind them (layers, idempotency, validation, security and roadmap), see [docs/snowflake-design.md](../../docs/snowflake-design.md).

| Script | Layer | What it does |
|---|---|---|
| [`typed-analytics.sql`](typed-analytics.sql) | RAW → typed → reports | Profiles the first RAW batch, checks source uniqueness, builds `PATIENT_TYPED`, `OBSERVATION_TYPED` and `APPOINTMENT_TYPED` with insert-only `MERGE`, validates them back to RAW, runs the three reports and the nine rule tests |
| [`firely-demo-reports.sql`](firely-demo-reports.sql) | Reports | The three reports on their own: cohort record presence, glucose timeline, appointment-linked information availability |
| [`fc30-load-and-report.sql`](fc30-load-and-report.sql) | Stage → RAW → typed → view | Loads the 30-patient failure-case batch, builds its typed tables, holds visit requirements in a configuration table, and computes availability in `APPOINTMENT_FC30_REPORT` |
| [`bridge-load.sql`](bridge-load.sql) | Stage → RAW | Loads the SIU^S12 appointment-bridge batch (`FORCE = FALSE`, explicit file list) |
| [`bridge-verification.sql`](bridge-verification.sql) | Checks | SELECT-only checks for the bridge batch: counts, the configured glucose rule's result, the full-payload export used by the reconciler, and the 30-patient summary |
| [`Snowflake-Coverage-Demo.sql`](Snowflake-Coverage-Demo.sql) | Semantic layer | Read-only Cortex Analyst demo questions over the Phase 1 coverage views, with offline benchmarks to check against |

Batch-specific SQL lives next to each batch:
- **Original pipeline:** [`analytics/sql/<batch>/`](../sql/synthetic-20261004T225801Z-5dd08717/), generated by [`prepare_snowflake.py`](../prepare_snowflake.py). It covers access, external-stage load, reconciliation, the repeat load and the internal-stage fallback.
- **Portal refresh:** the numbered scripts in [`hl7-portal-refresh-…/`](../batches/hl7-portal-refresh-20261007T183326824850Z/).
- **Phase 1:** [`datasets/phase1-fhir-examples/`](../../datasets/phase1-fhir-examples/), a direct S3 external-stage load with a fail-closed validation block.

The Streamlit dashboard is in [`../dashboard/`](../dashboard/).
